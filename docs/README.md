# FireGrounder: Fire-Base Grounding

This project predicts the 2D contact point at the base of a fire, not a
segmentation mask and not the top of the flame.

Input: an RGB image, video frame, or webcam frame.

Output:

```text
[p_fire, x_norm, y_norm]
```

- `p_fire`: probability that fire is present.
- `x_norm`, `y_norm`: normalized fire-base coordinates in `[0, 1]`.
- The point is meaningful only when `p_fire >= threshold`.

## Important Dataset Decision

`fire_ground_dataset/dataset_labels.json` is required for V3 training and
evaluation. It contains 6,500 records generated by the SAM3/HomeFire data
preparation workflow:

- 4,509 records with fire;
- 1,991 records without fire;
- `p_fire` stores the normalized fire-base point.

The folder does **not** contain the original image files. The JSON paths point
to a Kaggle mount such as `/kaggle/input/.../home-fire-dataset/...`. Therefore
you must attach or download the corresponding HomeFire images as well.

`fire_ground_dataset/stream_cache.jsonl` is only a resume cache for the SAM
labeling stage. V3 does not read it. It can be kept for reproducing labeling,
but it is not required for training or inference.

`dataset_labels (1).json` is a different legacy dataset with 1,034 records.
It is not the current 6,500-sample V3 dataset. Do not let automatic discovery
select it for the main V3 experiment.

## Recommended Distribution Strategy

Yes, you can put the code on GitHub and clone it on another machine. The
recommended split is:

1. GitHub: Python files, notebook/script, README, `requirements.txt`, and the
   small label JSON.
2. Kaggle Dataset or a private storage bucket: original image dataset and
   trained checkpoints.
3. Git LFS or a GitHub Release: checkpoints that you explicitly want versioned.

Do not store the raw image collection in a normal Git repository unless its
license and size make that appropriate. `last.pth` is about 102 MB and exceeds
GitHub's normal 100 MB file limit. The V2 checkpoints are also better managed
with Git LFS, Releases, or Kaggle Dataset storage.

### GitHub workflow

On the source machine:

```bash
git init
git add README.md HANDOFF.md requirements.txt .gitignore *.py *.ipynb fire_ground_dataset/dataset_labels.json
git commit -m "Prepare FireGrounder V3"
git branch -M main
git remote add origin https://github.com/<account>/<repository>.git
git push -u origin main
```

On the target machine:

```bash
git clone https://github.com/<account>/<repository>.git
cd Fire_Segmentation
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Linux/macOS:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Install a CUDA-compatible PyTorch build separately when the target machine
has an NVIDIA GPU. On Kaggle, do not replace the preinstalled CUDA/PyTorch
stack unnecessarily; usually install only the missing packages:

```bash
pip install -q timm matplotlib
```

## A-Z: Run V3 on a Local Machine

### A. Obtain the image dataset

Download the same HomeFire image dataset used to produce
`fire_ground_dataset/dataset_labels.json`. Keep the directory structure if
possible:

```text
home-fire-dataset/
  train/images/...
  val/images/...
  test/images/...
```

The repository currently contains labels, not these images.

### B. Smoke-test the V3 code without training

From the project root:

```bash
python -m py_compile firegrounder_v3.py inference_v3.py notebook4_v3_fpn.py
python notebook4_v3_fpn.py
```

The default flags are `RUN_TRAIN=False` and `RUN_EVAL=False`. The smoke test
creates random tensors only and does not train.

### C. Train V3

Edit the configuration at the top of `notebook4_v3_fpn.py`, or use environment
variables without modifying the file:

PowerShell:

```powershell
$env:FIRE_RUN_TRAIN="1"
$env:FIRE_JSON_PATH="fire_ground_dataset/dataset_labels.json"
$env:FIRE_IMAGE_ROOT="D:\\datasets\\home-fire-dataset"
python notebook4_v3_fpn.py
```

Linux/macOS:

```bash
FIRE_RUN_TRAIN=1 \
FIRE_JSON_PATH=fire_ground_dataset/dataset_labels.json \
FIRE_IMAGE_ROOT=/data/home-fire-dataset \
python notebook4_v3_fpn.py
```

Outputs are written to `v3_outputs/` locally, or `/kaggle/working/` on Kaggle:

- `best_v3_fpn.pth`;
- `train_history_v3.json`;
- optional `v3_val_preview.png`.

The script uses the fixed seed 42 and a 15% validation split. It applies
coordinate-safe horizontal flipping (`x_new = 1 - x`) and early stopping.

### D. Evaluate an existing V3 checkpoint

```powershell
$env:FIRE_RUN_EVAL="1"
$env:FIRE_JSON_PATH="fire_ground_dataset/dataset_labels.json"
$env:FIRE_IMAGE_ROOT="D:\\datasets\\home-fire-dataset"
$env:FIRE_CHECKPOINT_PATH="D:\\models\\best_v3_fpn.pth"
python notebook4_v3_fpn.py
```

The report includes classification metrics and localization mean, median, P90,
and the percentage of fire images within 5, 10, and 15 pixels. It is saved as
`v3_eval_metrics.json`.

### E. Run inference on an image

```bash
python inference_v3.py --mode image \
  --input fire.jpg \
  --checkpoint v3_outputs/best_v3_fpn.pth \
  --output fire_v3_pred.jpg \
  --device auto --show
```

For a headless machine, omit `--show`. The output uses the original image
dimensions when drawing the predicted point.

### F. Run video or webcam inference

```bash
python inference_v3.py --mode video \
  --input fire.mp4 \
  --checkpoint v3_outputs/best_v3_fpn.pth \
  --output fire_v3_result.mp4 \
  --device auto

python inference_v3.py --mode webcam \
  --checkpoint v3_outputs/best_v3_fpn.pth \
  --device auto --show
```

The existing V2 checkpoint still uses the old entry point:

```bash
python inference.py --mode image --input fire.jpg --checkpoint best_mobilenetv4.pth
```

## Checkpoints and Compatibility

- `best_mobilenetv4.pth` is V2 and must be loaded with `inference.py`.
- `best_v3_fpn.pth` is V3 and must be loaded with `inference_v3.py` or
  `load_checkpoint_v3`.
- V3 loading validates `model_version` and rejects a V1/V2 checkpoint.
- Do not overwrite or rename the V2 checkpoint while experimenting with V3.

## What Has Not Been Proven Yet

V3 has passed an architecture/loss smoke test only. It has not been trained in
this repository session, so no V3 F1, MAE, latency, or improvement claim is
valid yet. Acceptance requires V2 and V3 on the same split, threshold curve,
held-out test set, latency benchmark, and hard-negative analysis.

## Troubleshooting

### `Image not found`

The labels are present but the original image dataset is not mounted. Set
`FIRE_IMAGE_ROOT` to the folder containing `train`, `val`, and `test`, or attach
the matching Kaggle Dataset.

### CUDA out of memory

Lower `BATCH_SIZE` from 48 to 24 or 16. Keep `IMG_SIZE=256` for comparable
metrics, or record any resolution change in the evaluation report.

### OpenCV window does not open

Remove `--show` and use `--output` for headless servers/Kaggle.

### GitHub rejects a checkpoint

Use Git LFS, a GitHub Release, or Kaggle Dataset storage. Do not force a file
larger than GitHub's normal 100 MB limit into the repository.
